### 明确的实现边界

- 业务日期统一为 Asia/Shanghai；尚未提供用户自选时区。
- 未来预测使用既有预测逻辑；仅到期账期持久化，不预先创建全部未来 `planned` 行。
- 首页聚合待办、餐饮、提醒、账期、计划及未来30天纪念日筹备；纪念日筹备支持预览、确认、忽略本次和完成状态联动。
- 协作已补所有者/空间管理员带原因转派与双端分页审计。双端已提供本人逐记录字段及图片/链接引用预览；权限仍按业务域生效，不支持逐对象授权。
- `GROUP-B` 共同支出分摊按原设计保留为后续可选批次，本次无分摊/结清台账。
- 报告提供三条基于事实快照的规则候选草稿，用户可选择、修改后采纳一个后续行动；候选明确标记为规则生成，目前未接入模型生成建议。
- 持久化执行计划接入餐饮、报告待办及 AI 新建笔记/日记/纪念日/待办、购物添加；其余 AI 写工具仍待迁移。
- 失败出账按 1、2、4、8、16、32、60 分钟退避，之后上限60分钟；到期后由下一轮调度尝试，手动重试可提前执行。
- 功能开关在服务端强制执行；双端新增功能面板及主要动作入口同步隐藏，约30秒刷新一次；已有通用编辑页面仍由后端最终校验。

这些边界尚未覆盖原设计的全部扩展项；不得将本交付描述为原设计所有子项及上线门槛均已完成。

## 2. 核心规则

### 2.1 账期与真实账单

新建规则默认 `manual_confirm`，旧数据迁移为 `auto_record`。唯一业务键为所属用户、来源类型、来源 ID、到期日，另有账单 ID 唯一约束。定时任务、自动化和手动失败重试均走统一服务，来源行锁及单期事务保证一次生成。

人工模式生成 `pending`，不影响真实消费统计。确认写入实际账单与更新实例处于同一事务；实际金额必须为正且满足金额精度，账户/分类必须属于本人，支付日期不得晚于业务当天。跳过、取消需填写原因。可见状态包括 `pending/payment_failed/posted/skipped/cancelled/voided`。真实账单被编辑或软删除后，账期列表/详情会同步实际金额和作废状态，不重新出账。

订阅按原日期锚点计算月末/闰年日期。已取消订阅不恢复；新规则暂停恢复不自动补欠期。补欠期先展示最多 100 期，只生成待确认实例，保留暂停状态。旧 `sub_ID_date` 账单可关联复用，避免迁移后重复消费。已经漂移的历史锚点无法猜回，迁移沿用现有日期。

### 2.2 预览和重试

规则变更、购物转换和执行计划预览有效期 15 分钟。提交重新检查权限、源快照及当前状态；源变化需重新预览。购物预览提交采用当前锁定读取，避免事务旧快照覆盖并发编辑。

账期动作、购物条目动作、提醒动作需要 `requestId`，同一用户同一键只保存一份结果；请求内容变化拒绝。同一动作网络重试应复用原键及原参数。回执目前不自动清理，后续清理策略须至少保留 90 天。购物结算使用批次请求键，补记支出另有请求键；预览提交及计划执行以持久化 ID 去重。

执行计划单步事务包含业务写入和步骤结果。只重试失败/未完成步骤；成功步骤不重跑。运行租约 15 分钟，按步骤续租并检查执行令牌。补偿只允许未被后续编辑/引用的支持对象；购物外部变化及实际财务结果不会被一键删除。

### 2.3 采购数量和结算

份数支持三位小数，必须大于零。规范化全角文本；g/kg、ml/L 可换算，其他计数单位不跨单位合并；无法解析的“适量”等保留原文并提示人工核对。调整日期范围只替换本次来源贡献，保留其他来源。已购和已结算行不会静默改写。

结算每次 1–200 个已购且未结算条目，按 ID 排序加锁；整行结算，不支持部分采购。勾选记账时由用户输入总额和私人账户，不按食材估价。一个批次至多关联一条实际支出；共享清单成员不会因此读取他人账户及批次财务明细。

### 2.4 联网和共享

服务端每次写入重新校验权限；viewer 仅可读。成员退出或降权在事务内清理其不再具备编辑权限的未完成认领/负责人，已经完成的业务记录保留。

App 离线代理禁止新账期、提醒、执行计划、报告行动、采购转换/结算、空间管理操作；记账、订阅、餐饮、购物写入需联网。断网时拒绝提交，表单调用未成功不应关闭；不会写入离线队列并假报成功。个人笔记等原离线功能保留。共享模块离线读取限制为当前用户拥有的缓存，在线列表缓存不再新增他人数据；已补定向物理清理（见第7节），App 真机行为仍需上线前验证。

## 3. API 契约

沿用项目 `AjaxResult`，成功业务内容在 `data` 中。错误返回可读 `msg`，新增业务错误附 `errorCode`；权限不足不返回对象快照。所有用户 ID 从登录态获取，不相信请求传入的 owner。

| 方法与路径 | 请求/用途 |
|---|---|
| GET `/life/features` | 当前用户六个功能开关 |
| GET `/life/action-center` | `scope=personal或group`、`groupId`、`date`、`pageNum`；行动聚合 |
| GET `/life/action-center/spaces` | 可见且有效空间 |
| GET/PUT `/life/action-center/preferences` | 常用入口白名单、最多 6 项、版本校验；字段以控制器为准 |
| GET `/charge/instances` | `pageNum/pageSize/sourceType/sourceId/status`；最多100条/页 |
| GET `/charge/instances/{id}` | `instance` 和操作回执 `history` |
| POST `/charge/instances/{id}/{action}` | `confirm/skip/payment-failed/cancel`；如下方示例 |
| GET `/charge/instances/failures` | 当前用户生成失败 |
| POST `/charge/instances/failures/{id}/retry` 或 `/dismiss` | 重试原账期/忽略失败记录 |
| POST `/charge/rules/change-preview` | `sourceType/sourceId/changes`；原规则和变更预览 |

| GET `/reminder/events` | 当前用户事件 |

| POST `/mealPlan/shopping-preview` | `listId/startDate/endDate` |
| POST `/mealPlan/shopping-commit` | `previewId` |
| POST `/shoppingItem/{id}/{action}` | `claim/release/fulfillment`；`requestId/expectedRevision/state` |
| POST `/shoppingList/{id}/checkout` | `requestId/purchasedItemIds/recordExpense`；记账时附金额等 |
| GET `/shoppingList/{id}/batches` | 本人的采购批次 |

| GET `/lifeReport/insights/{id}/sources` | `pageNum`；每页30条本人来源 |

确认实例示例（账户、分类及实例 ID 需替换为当前用户真实 ID）：

```json
{"requestId":"charge_20261024_001","expectedRevision":0,"actualAmount":29.90,"accountId":1,"classificationId":2,"paidAt":"2026-10-24"}
```

购物结算示例：

```json
{"requestId":"purchase_20261024_001","purchasedItemIds":[11,12],"recordExpense":true,"totalAmount":58.30,"accountId":1,"classificationId":2,"paidAt":"2026-10-24"}
```

执行计划示例（预览成功后再 POST 返回计划 ID 的 `/confirm`）：

```json
{"title":"检查订阅支出","steps":[{"toolCode":"todo.create","input":{"content":"核对本月订阅是否仍需续费","dueDate":"2026-10-30"}}]}
```

白名单步骤为 `todo.create/meal.create/shopping.generate`。餐饮必须指定实际份数；关联菜谱必须可用且权限符合要求。错误码包括 `REVISION_CONFLICT/IDEMPOTENCY_CONFLICT/SOURCE_UNAVAILABLE/FEATURE_DISABLED` 等，客户端应显示服务端中文原因，版本/来源过期需刷新预览，不能仅替换版本后盲目重发。

## 5. 配置、发布与回退

本地默认六项均开启。测试/生产先明确配置允许用户，避免省略配置导致全量：

```yaml
pnkx:
  features:
    actionCenterV2: { owners: "1,2" }
    chargeInstanceV2: { owners: "1,2" }
    reminderEventV2: { owners: "1,2" }
    shoppingPlanV2: { owners: "1,2" }
    operationPlanV2: { owners: "1,2" }
    reportActionV2: { owners: "1,2" }
```

`owners: "*"` 全量，空字符串关闭；按当前部署配置加载方式重启生效。关闭账期生成不会回退到旧直接写账单逻辑。建议相关功能对同一用户一起启用，以免计划能预览但依赖功能未开放。

发布步骤：

1. 在生产备份的隔离库核对 Flyway 版本无冲突，备份数据库；记录账单条数、实际总额和来源重复键。
2. 停止旧版订阅/周期/自动化写入实例及定时任务，等待运行事务结束。禁止旧直写版本和新版本混跑。
3. 应用迁移并验证旧费用总额未变，部署新版后端；配置少量允许用户，部署双端资源。
4. 使用专用测试账户验证确认一次、重复请求不重复记账、跨用户拒绝、购物预览失效、失败步骤重试、已处理提醒停止投递。
5. App/小程序真机验证断网保留输入、重新联网、通知深链、空间退出和旧缓存；验证后逐步扩大允许用户。
6. 观察生成失败、唯一键冲突、未处理账期、计划部分失败及提醒积压；异常关闭对应开关并保留证据。

回退优先关闭新功能和暂停相关任务；保留新表及回执，不运行破坏性 DROP，也不恢复旧直写任务。若必须回退旧二进制，需要先做账期/真实账单对账和兼容评审；不能声称仅还原代码即可安全回退。

## 7. 继续开发记录：入口权限、缓存、转派和退避

### 7.1 双端功能入口与缓存

新增能力查询缓存和 FeatureGate：未获取允许结果不挂载业务组件，同账号并发挂载合并请求，账号切换或退出立即隐藏，旧账号迟到响应不得开启新账号功能。服务器不可达时隐藏新增入口，恢复后再次查询。状态约30秒刷新；关闭时服务端即时拒绝写入，前端可能等待下次刷新才隐藏。

## 13. 行动中心操作防重复与提醒重试

2026-10-25：双端待办完成、出账失败处理、提醒已读/稍后提醒/忽略操作增加按对象的处理中锁。同一对象请求未结束时禁用相关按钮，并在调用层抑制重复点击；不同对象可独立处理。失败保留当前事项并显示操作提示，不再产生未捕获的界面操作异常。

## 14. 单步创建草稿编辑与重新确认
