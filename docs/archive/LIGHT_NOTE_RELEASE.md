## 3. 私有文件配置

```yaml
pnkx:
  private-files:
    root: /srv/pnkx-private-files
    quota-bytes: 209715200
spring:
  servlet:
    multipart:
      max-file-size: 20MB
      max-request-size: 22MB
```

- 默认根目录 `${user.home}/.pnkx-private-files`，默认每用户 200 MiB、单文件最大 20 MiB、最多 1000 个目录。
- 存储目录必须在公开上传目录外，不允许符号链接；给服务进程读写权限。数据库和对象目录应协调备份，多实例部署需使用共同持久卷。
- 所有下载/预览先验证 owner；随机 object key 不对客户端开放，重命名只改展示名称。上传期间持有用户配额锁，失败回滚并清理对象。
- 图片/PDF/有效 UTF-8 文本可预览，其他内容按附件下载。没有 OCR 或 Office 正文解析；搜索仅名称/MIME。
- 回收站仍占用配额，文件暂不自动物理清理。不提供可绕过引用检查的批量删除脚本。
- PC/H5 支持普通文件选择上传；原生 App 当前使用图片选择器，PDF 可预览，其他格式提示使用 PC 下载。原生通用文件选择器不在本轮实现范围。

## 4. App 离线升级

旧 `_doc/pnkx_offline.db` 没有可靠的统一账号归属。新版按当前登录 ID 使用 `_doc/pnkx_offline_<id>.db`，匿名不打开数据库；旧库保留原状，但不自动导入，避免把上一个账号待上传数据归给当前账号。

**升级前应在旧版同步完待上传数据，或导出未同步笔记；不能把旧库存在等同于新版已恢复草稿。** 无法同步的旧数据保留原文件，需后续在确认实际归属后恢复。新账号库可从服务器重新拉取；不删除旧库做“清缓存”。

新同步协议 `/workspace/notes/changes` 使用 `n2:<owner>:<seq>` 游标。服务端用户级锁保证变更序号与提交顺序一致；客户端在页面全部落库后才推进游标。失败重试、墓碑重放不会覆盖待上传笔记。变更日志暂不截断，不承诺已实现基于设备水位的自动清理。旧 `/offline/sync/note` 兼容接口保留。

## 5. 问答、规则整理与重复待办边界

问答：关键词/类型/创建日期/标签筛选，最多 12 条、约 16000 字正文上下文；来源截断或匹配更多记录时返回覆盖不足。全类型检索依次收集笔记、剪藏、待办，范围过大应缩小过滤。暂无向量语义召回、文件正文或自动全库总结。

PC 使用 SSE 展示生成进度；完整答案经过权限和来源指纹复核后统一显示，避免将失效资料的答案提前逐字展示。App 使用长请求及独立取消接口。每用户最多一个生成请求，120 秒超时，最多 30000 字输出；取消会释放模型订阅，但提供商可能已产生部分费用。代理需允许至少 130 秒请求并关闭 SSE 缓冲。请求失败不自动重试收费调用，手动重试生成新 requestId；取消先于生成到达也会阻止迟到请求。

问答保存为私有持久化草稿；打开或应用时再次校验来源。来源失效或改变需要重新提问。用户可编辑类型、标题和正文，确认后只创建新笔记/待办并关联引用，不自动改写原资料。应用按请求幂等；取消/失败的半截答案不能应用。记录输入/输出字符数和耗时，不把字符数当作 token 或账单金额；列表显示最近 50 条。

整理：无标签、空正文、空笔记标题、抓取失败、同批精确重复正文。每批最多 100 条，重复候选仅比较本批同类型笔记/剪藏；不把重复标题或无说明待办当成重复/空资料。空内容/重复/失败建议应用后进入收件箱等待人工核查；空标题建议经笔记服务改名。没有全库重复索引、长期未读规则或批量 AI 拆任务。

重复待办：每日/每周指定日/每月指定日/完成后间隔，按指定时区生成当天及以前到期实例；每系列每轮最多补偿 31 次。月末不足指定日期用月末，DST 缺失时间顺延，重叠时刻只生成一次。删除完成型当前实例按跳过本次处理，从发现删除的当日计算下一次间隔。

“仅本次”在原待办详情编辑；“以后”改变尚未生成实例；“整个系列”还更新既有未完成实例标题和提醒，已完成历史保留。既有实例日期不会整体平移。暂停阻止新生成；使用“整个系列”暂停还解除未完成实例提醒。“以后”暂停保留既有实例提醒。当前不预生成远期实例，因此没有待删除的远期任务副本。

历史恢复最多保留 50 版；目录缺失恢复到根目录，而非新增“恢复的笔记”目录。正文含已失去权限的新引用时，还原会拒绝，需要用户处理引用，不静默丢弃关系。笔记/剪藏/文件回收站支持恢复，尚未开放永久删除和自动过期清理。

## 6. 人工验收矩阵

| 场景 | 预期 |
|---|---|
| 两普通账号枚举笔记/目录/标签/文件 ID | 不能读写对方私有数据，搜索/数量/反链不泄露 |
| 群组待办共享后撤销 | 搜索和引用立即按当前权限过滤，已生成问答草稿不能继续打开/应用 |
| PC/App 同时编辑同一 revision | 一次成功、另一次 409；失败端保留可比较/另存草稿 |
| 保存请求中继续输入/切换笔记 | 新输入仍标记待保存，不串到其他笔记 |
| 飞行模式新增/修改，超时重试后联网 | UUID/队列幂等，冲突不自动覆盖，成功回写 revision |
| 删除/恢复后离线设备重新连接 | 墓碑/新修订可拉取，失败中途重试不跳页；待上传内容受保护 |
| 切换账号及旧请求迟到 | 独立 SQLite 文件；旧响应不写新账号缓存 |
| 标签合并/旧标签回填/筛选 | 投影与关联一致，分页计数为过滤后的结果 |
| 剪藏转换连续点击、问答草稿重复确认 | 只创建一个目标，来源链接可回跳 |
| 历史还原遇到并发更新 | 409，不覆盖当前笔记 |
| 文件大于 20 MiB、并发超配额、上传断开 | 请求失败不遗留已计费元数据/对象；正常下载含鉴权及安全响应头 |
| App 图片/PDF/文本、PC/H5 文件操作 | 上传、目录移动、预览、回收站恢复完整闭环；未知格式按附件 |
| 重复任务 Quartz 重跑、完成后间隔、暂停 | 同日期不重复生成；完成型等待完成或跳过；实际提醒只达一次 |
| 问答无正文、来源变更、取消、模型未配置 | 无正文不调用模型；来源变更拒绝交付/应用；取消停止订阅；错误可见且可手动重试 |
| 一次真实默认模型问答 | 来源正确、回跳成功、字符/耗时记录可见；另外核对提供商实际账单 |

自动化结果见任务清单。尚未验证实际手机、真实通知送达、真实提供商账单、完整业务库迁移耗时和拟定性能指标。
