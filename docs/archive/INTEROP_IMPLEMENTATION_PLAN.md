# Pnkx 功能互通实施方案

> 创建于 2026-09-24。目标：优先补齐已有能力的跨端闭环，再建设跨模块自动化，避免继续增加孤立 CRUD 页面。

## 当前互通基线

| 能力域 | 已互通能力 | 本轮补齐 | 后续演进 |
| --- | --- | --- | --- |
| 记账 | 账户、分类、账单、统计 | 移动预算、周期记账、纪念日关联、导出分享、预算通知 | 自动对账与多人预算 |
| 提醒 | 待办、纪念日、经期、订阅 | 统一设置组件、渠道偏好、免打扰、深链、失败重试 | 规则化升级与更多来源 |
| 日历/首页 | 待办、纪念日、经期、账单 | 订阅、餐饮计划、今日聚合和详情路由 | 购物计划、阅读目标、生活报告 |
| 搜索 | PC 文章/待办/日记/笔记/账单 | 扩展至 10 类内容并增加移动入口 | 时间/标签筛选和 AI 问答 |
| 离线 | 日记、待办、账单、笔记、纪念日 | 扩展购物、菜谱、餐饮、订阅、经期、预算、周期记账、书籍/阅读进度 | 真机弱网压测与更细粒度字段合并 |
| AI | 单模块新增和分析能力 | 纳入统一规划 | 工具注册表、复合任务、确认与回滚 |

结论：当前最适合继续互通的是“时间轴 + 提醒 + 搜索 + 离线”四条公共基础设施；下一阶段新增功能应优先建设自动化规则和 AI 工具层，而不是继续增加孤立页面。

## 一、实施原则

1. 先修数据正确性和已承诺但不完整的能力。
2. 后端能力、PC 管理端、uniapp 移动端按同一验收口径交付。
3. 涉及自动写入的功能必须保留确认、幂等、审计和失败重试机制。
4. 日记、经期、账单等隐私数据默认私有，任何发布或家庭共享必须显式授权。
5. 每个批次至少完成编译或自动化测试，并同步更新本文档状态。
