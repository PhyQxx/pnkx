## 0. 一句话目标

把「约 20 个功能模块、95+ 个页面、3 Tab + 15 宫格、6 个 AI 入口、4 套文件存储」收敛为：

- **移动端**：4 Tab（今天 / 生活 / 资料 / 我的）+ 全局搜索 + AI 悬浮球 + 快捷录入 FAB
- **PC 端**：一级侧栏（今天 / 生活 / 资料 / AI 助手 + 内容发布）+ ⌘K 命令面板 + 顶栏快捷录入

同时建立**双端同源**的设计令牌、页面模板、组件规范和动效体系；私有文件统一到「FTP 存储 + 5 GiB/人配额」。

## 1. 项目全景梳理

### 1.1 四端一链

| 端 | 技术 | 角色 | 本方案范围 |
|---|---|---|---|
| pnkx-uniapp | Vue3 + uni-app（95 vue / 约 3.2 万行） | 主用户端（App/小程序/H5） | UI/UE 全部重做（§3） |
| pnkx-ui | Vue3 + Element Plus（RuoYi 式） | 管理端/PC 工作台 | 整合为 PC 工作台（§4） |
| 博客前台 | Nuxt | 公开内容发布 | 不动，仅对齐品牌色 |
| web-clipper | MV3 插件 | 资料输入链 | 不动 |

### 1.2 功能资产盘点（按域）

- **生活管理域**：记账（账户/分类/预算/周期/模板/导出/AI 解析）、待办（子任务/看板/重复系列）、日记、纪念日、家庭日历、购物清单、菜谱与膳食计划、订阅管理、经期记录、书城、情侣卡券、壁纸站、提醒中心、生活自动化、生活报告。
- **资料工作台域**（2026-10 新增）：资料中心（笔记/剪藏/文件/待办统一视图）、统一层级标签、双链引用、收件箱、整理建议、回收站与版本历史、AI 资料问答、个人文件库、12 类全局搜索、RSS、浏览器剪藏。
- **横向基础设施**：AI 助手（意图识别/工具注册/草稿确认）、统一提醒（WebSocket/邮件/uniPush）、离线同步、家庭/情侣空间、SSO。
- **内容发布域**：博客文章/相册/视频/友链/留言/邮件订阅/分享资源/访客统计。

### 1.3 入口现状问题（收敛前）

- 移动端：Tab 3 个 + 生活助手宫格 15 项（菜谱/膳食/购物双路径）；「记一笔」4 处入口、「加待办」6 处；AI 入口 6 处；资料中心藏在首页卡片后；`pages_system/search` 重定向壳与 `pages/common` 两页为死代码。
- PC 端：RuoYi 多级菜单树 + 工具栏，资料中心为 `/resources/hub` 单页（原型风），与管理端视觉割裂（主色 `#0ea5e9` vs App `#4F86F7`）。

### 1.4 UI/UE 技术债清单（双端）

移动端（pnkx-uniapp）：
1. **令牌有、执行无**：`uni.scss` 已是完整 Glacier 设计系统（主色 `#4F86F7` + 模块色 + 灰阶 + 字号七档 + 间距 + 圆角 + 阴影 + 动效令牌），但页面存在 665 处硬编码 hex、128 种色值；`pages.json` 原生标题按钮三色并存。
2. **全局样式靠 `!important` 反向补丁**：`.subpage-shell` 对约 40 个页面类名刷统一玻璃卡片（63 页已套），workspace 系列未套。
3. **死代码**：colorui.css 5143 行（0 使用）、liu-drag-button、uni-nav-bar 装而未用、easycom + main.js 双重注册、IconSelect/IconPicker 双份。
4. **图标四体系**：uni-icons / SvgIcon 拼音拼 URL（脆弱）/ iconfont / 模板 emoji（34 处）。
5. **通用交互无封装**：空态 3 种做法（NoData 仅 2 处使用）；`$modal` 与原生 API 并行（uni.showToast 192 处 / showModal 40 处）；表单防重零星 16 处；无骨架屏。
6. **列表交互三种模式**：scroll-view 刷新加载（8 页主流）/ 原生下拉（首页）/ 按钮翻页（workspace 系列）。
7. **超长单文件**：record/add.vue 1627 行、pages/index.vue 1367 行；样式行数普遍 ≥ 模板。
8. **无暗黑模式**，背景依赖固定浅色大图。
9. **动效空白**：无转场策略、`@keyframes` 仅 6 处。
10. **导航栏策略混乱**：3 个 tab 页各自手写自定义导航；子页面原生导航栏。
11. **页面通信靠 onShow 全量刷新**（23 页），零事件机制。

PC 端（pnkx-ui）：
12. **双端视觉不同源**：独立 design-tokens（sky `#0ea5e9` + slate），与 App 两套体系。
13. RuoYi 多级菜单与"个人工作台"定位不符；千行组件（如 record.vue 1772→870 已拆过一轮）仍需持续治理。

## 2. 功能模块重新划分（双端同构）

### 2.1 划分原则

1. **入口最少化**：移动端一级入口 4 Tab + 3 浮层；PC 一级入口侧栏 4+2 项 + ⌘K。任何功能 ≤3 步可达。
2. **渐进披露**：首层只放「高频 + 今日相关」，完整分支收进板块内部（生活管家 / 设置 / 管理类全部下沉二级）。
3. **领域服务 + 横向能力**：领域模块（账本/日记/待办…）保留原路由与数据，不推翻；**标签、状态、附件、搜索、回收站、周期规则、AI 七项横向能力收归公共服务，新功能禁止再自建**。
4. **内容流水线**：生活域产生记录 → 资料域组织知识 → 公开域发布内容。资料中心是所有「内容」的统一之家。

### 2.2 五域模型

```
┌─ 今天 Today ─── 时间轴·提醒·今日概览·继续阅读·快捷录入
├─ 生活 Life ──── 生活管家（账本/日历/购物/菜谱/订阅/纪念日/卡券/姨妈/书城/自动化/报告）
├─ 资料 Knowledge ─ 笔记·剪藏·文件·待办四类资源统一库 + 标签/双链/整理/问答/回收站
├─ AI ─────────── 统一助手（技能化：记账解析/资料问答/生活报告/剪藏整理/搜索总结）
└─ 我的/系统 ──── 移动端「我的」Tab；PC 侧栏「内容发布」（博客/系统管理）
```

## 3. 移动端方案（pnkx-uniapp）

### 3.1 信息架构：3 Tab → 4 Tab

**tabBar：今天 / 生活 / 资料 / 我的**

- 「资料」提升为一级 Tab——10 月刚建成的核心资产不应藏在首页卡片后面。
- 「生活助手」更名「生活」，内部只保留**生活管家一个聚合入口**，宫格平铺 15 项的模式取消。
- AI 不占 Tab：全局悬浮球（资料 Tab 让位于底部工具条时隐藏）。

### 3.2 各板块内部结构

**今天（pages/index 重构）**

```
今天
├─ 顶栏：问候 + 日期（在一起 N 天）+ 通知铃铛（红点 ping）
├─ 搜索条（→全局搜索，全 Tab 统一组件，尾部 AI 徽标）
├─ 概览卡：今日支出（count-up）· 待办进度条 · 互切
├─ 我的资料卡：未整理 N 条 · 继续阅读最近 3 条（→资料 Tab）
├─ 今日时间轴：记账/待办/卡券/订阅/纪念日按时间合并，待办带勾选
├─ FAB 快捷录入（展开：记一笔/待办/日记/剪藏链接）
└─ 下拉刷新整页
```

**生活（pages/function 重构）**

```
生活
├─ 搜索条（同上）
├─ 高频四宫格：账本 · 日历 · 待办 · 日记      ← 唯一平铺层
└─ 生活管家（二级聚合，分组折叠）
   ├─ 家庭：日历 · 购物清单 · 菜谱库 · 膳食计划 · 订阅管理
   ├─ 记录：日记 · 纪念日 · 姨妈助手 · 情侣卡券
   ├─ 阅读：书城
   └─ 自动化：生活自动化 · 生活报告 · 提醒中心
```

**资料（workspace 系列升为 Tab 首层）**

```
资料
├─ 顶栏：搜索条（域内搜索，尾部「全局」切换）
├─ Segment：收件箱(N) · 全部 · 继续阅读
├─ 类型 Chips：全部/笔记/剪藏/文件/待办 + 标签筛选（收进抽屉）
```

## 7. 动效设计（双端）

### 7.1 原则与令牌

三原则：**有目的、够短、可关**（`prefers-reduced-motion` 全局降级）。

```
时长：$duration-fast 120ms（按压/勾选/chip）
     $duration-base 240ms（弹层/卡片/PC 详情面板）
     $duration-slow 360ms（FAB 展开/PC 侧栏折叠 280ms 页面切换 180ms 单列）
缓动：$ease-out-quint cubic-bezier(.22,1,.36,1)  进入
     $ease-in-quart  cubic-bezier(.64,0,.78,0)   退出
     $ease-spring    cubic-bezier(.34,1.56,.64,1) 弹性
性能红线：只动 transform/opacity；列表 >50 项关 stagger；backdrop-filter 限卡片级。
```

### 7.2 转场体系

| 场景 | 移动端 | PC 端 |
|---|---|---|
| 页面切换 | 内容 fade 120ms + 上浮 8rpx | fade 180ms + 上浮 8px |
| push 详情 | 系统原生（保留侧滑返回） | — |
| 弹层 | 底部上滑 240ms + 蒙层 fade 180ms | 居中 scale .94→1 spring 220ms |
| 命令面板 | — | 下拉 scale .96→1 + fade 160ms |
| AI 层 | 从球位置 scale 弹出 320ms spring | 页面切换转场 |
| 侧栏折叠 | — | 宽度 224→64 280ms out-quint，箭头随动 |
| 筛选抽屉 | 右滑入 240ms | 左栏常驻无转场 |

### 7.3 微交互清单

**双端共用**：按压/hover 反馈（`.pressable` / `.hoverlift`）；勾选完成（对勾描边 240ms + 划线置灰 + 统计 count-up + 可撤销 toast）；数字滚动（进视口 400ms，tabular-nums）；卡片进场 stagger（30–40ms/张，最多 6 张）；骨架屏 shimmer 1.2s；Chip 选中 morph + spring；红点 ping 一次；空态插画呼吸 3s；AI 流式光标 530ms + 引用 stagger 滑入 + 草稿按钮 spring。

## 9. 私有文件存储决策（已定）

**决策：私有文件（`px_user_file`）存储后端从本地磁盘切换为 FTP 服务器，配额从 200 MiB/人 提升至 5 GiB/人；配额计算逻辑不变。**

现状与理由：

- 现状两套存储并行：公开资源（头像/记账凭证/相册）走 `/common/upload` → `FtpTool` → FTP（`ftp.path: /ftp/`，nginx 对外服务，**无配额**）；私有文件走 `UserFileService` 本地磁盘（`pnkx.private-files.root`，200 MiB 配额，`sum(byte_size)` 实时计算，回收站计入）。
- 问题：无配额的 FTP 装大头，真正的私有库反而 200 MiB（几个 PDF 就满）；本地存储依赖 Jpom 挂载卷，容器迁移要带数据。

方案（4 处改动）：

1. **存储后端抽象**：`UserFileService` 抽 `put(objectKey,file)` / `openStream(objectKey)` / `delete(objectKey)`；现有逻辑为 LocalBackend，新增 FtpBackend 复用 `FtpTool.uploadMultipartFile / previewFile(InputStream) / deleteServerFiles`；`pnkx.private-files.storage: local|ftp` 切换（开发环境保持 local）。
2. **私有性保证**：私有文件传 FTP 上**不在 HTTP 暴露路径下**的独立目录（如 `/pnkx-private/`，公开资源仍在 `/ftp/`）；下载/预览永远走 `/workspace/files/{id}/content` 授权接口流式转发。启动校验扩展：ftp 模式 fail-fast 校验私有目录不得位于 `ftp.path` 之下。
3. **配额调整**：`quota-bytes` 209715200 → 5368709120（5 GiB）；`used` 含回收站保留；UI 存储条按「X / 5 GB（含回收站 Y MB）」口径显示。
4. **迁移与清理**：存量本地私有文件一次性 scp 至 FTP 私有目录（objectKey 不变，无缝）；上传失败 try-catch 内 `deleteServerFiles` 兜底清孤儿（顺手修现有本地方案同款问题）。
