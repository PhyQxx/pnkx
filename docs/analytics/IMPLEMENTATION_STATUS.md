## 第三批 登录和回复评论

新增 login_submit/login_success/login_fail、reply_submit/reply_success/reply_fail。仅在表单校验通过后记录提交；登录以返回token为成功，回复以接口返回成功数据为准。接口拒绝、网络异常均记录失败。回复请求期间阻止重复提交。回复 targetId 为被回复评论ID，不保存正文或被回复人信息。

pnkx-ui 的功能事件、访问轨迹及操作成功率支持这两类功能。无需新的数据库迁移，仍要求001和002已执行。登录前后保持相同匿名访客和会话；队列发送时服务端认证身份可能已变化，因此身份转换分析以匿名访客和operationId关联，不推断每条事件发生时的登录状态。

本轮客户端9项、后端校验10项和Mapper绑定2项测试通过。真实登录与回复的浏览器端联调、数据库查询仍待完成。

## 第四批 注册激活与内容筛选

- 注册提交/成功/失败与账号激活提交/成功/失败分别记录。注册请求成功不代表账号已激活，注册与激活各自统计操作成功率，不强行跨设备关联。
- 注册表单增加请求中防重复提交；不记录账号、密码和激活令牌。激活请求仅在浏览器挂载后执行，避免SSR执行状态变更请求。
- 首屏业务事件早于app挂载完成时，自动建立页面上下文，后续挂载不重复计PV。
- 后台新增内容ID、目标ID、功能筛选；内容ID需结合页面类型，视频目标ID需结合视频功能，回复目标ID需结合回复功能。功能筛选会过滤所有指标，PV可能为0，页面有口径提示。
- 页面排行查询当前文章/视频标题，不存储历史标题快照；已删除内容保留ID并显示缺失提示。分类等非文章/视频内容暂不解析名称。
- 无新增数据库迁移。真实MySQL标题查询、筛选及浏览器激活链路仍需联调。

## 第五批 多步骤转化漏斗

新增 GET /admin/analytics/funnels，与统计页使用同一权限。管理端“转化漏斗”页签手动计算，修改相关筛选后清空旧结果。

三条链路：搜索提交→同次搜索成功→点击该次结果；正文位置达到50%→同一次页面访问提交评论→同次评论成功；打开AI→发送问题→同次回答完成。每一步按访客和会话组合去重，不是自然人数。显示三步会话数、总转化率、未完成会话数。未完成可能是仍在操作或跨窗口，不直接判定为永久流失。

所有事件必须在查询窗口内，按时间顺序推进；同一毫秒使用步骤顺序作为平局规则。评论限定相同pageViewId，结果限定相同operationId；AI打开只需同一会话内先于该次请求。失败重试若后续另一次操作完整成功，该会话仍计一次转化。

漏斗保留日期、页面、内容ID、访客、会话筛选，忽略功能和目标ID筛选以免删除前置步骤。限制20000条相关事件，超限不返回截断统计，提示缩小范围；大数据量后续再改为数据库聚合。页面/内容筛选也可能排除跨页面步骤，查看全站漏斗时应清空这两个筛选。

搜索点击现携带当前展示结果的operationId与目标文章ID，输入改变或关闭时清除关联。旧点击无operationId，无法补算该步骤，不应与新版本转化率直接比较。无需新增数据库迁移。

新增算法测试覆盖跨操作误关联、反序结果、跨页面评论、重复与同毫秒事件、跨会话误关联和正常转化。真实数据库查询与浏览器漏斗联调仍待完成。

本轮验证：客户端10项、后端18项测试共28项通过；两个前端生产构建、管理端改动ESLint和git diff --check通过。没有执行数据库迁移、生产部署或远端推送。

## 第六批 每日趋势与明细维护

- 统计接口返回北京时间每日PV、UV及活跃会话，查询范围内无数据日期补零。管理端新增PV/UV柱状图与精确数值表，沿用当前筛选，区间UV仍单独去重，不能相加每日UV。
- 新增只读 GET /admin/analytics/retention，返回开关、北京时间截止点、过期记录数及每次上限。管理端“数据维护”手动查看预览；不提供删除按钮。
- 新增 analyticsCleanupTask.run 定时任务入口。配置 pnkx.analytics.cleanup-enabled 默认false；只有显式设true并注册调度后才删除。此次开发没有修改运行环境配置、没有创建调度、没有删除数据。
- 截止点为北京时间当天减90天的00:00:00，只删除严格早于截止点的事件。每批1000条，单次最多10批，分批提交，失败时停止并由Quartz记录失败；下次执行继续处理剩余数据。
- 当前没有长期汇总表，清理会使已删除日期的趋势、轨迹和漏斗不可查询。上线启用前先确认保留策略和备份；页面已提示这一限制。

配置示例（部署环境应用配置，不是前端环境变量）：

```yaml
pnkx:
  analytics:
    cleanup-enabled: false
```

运维启用步骤：确认备份及只读预览→设为true并重启后端→在定时任务管理新增analyticsCleanupTask.run，建议每日低峰执行、禁止并发→确认调度器时区（若按北京时间03:30执行，cron为0 30 3 * * ?，需调度器使用Asia/Shanghai）→检查删除日志和过期数量。积压超过10000条可分多次调度处理。回退时暂停调度并将开关改false；已删除数据仅能从备份恢复。

新增5项测试：关闭时不访问数据库、部分批次提前结束、10批上限、北京时间截止边界、预览不删除。未执行真实MySQL删除或浏览器视觉联调。
