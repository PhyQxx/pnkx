# 访客分析开发交付

日期：2026-11-24。

## 已实现

- pnkx-client：生产默认启用、开发默认关闭，可用 NUXT_PUBLIC_ANALYTICS_ENABLED=true/false 覆盖；全部路由自动归类，随机访客和标签页会话、有效停留、队列重试、离页补报。
- 搜索、主评论/留言、AI助手的打开/请求/结果事件；异步结果关联原始页面和操作。
- pnkx-admin：批量校验、去重写入、IP限流、北京时间查询、概览/页面/功能聚合、分页轨迹、服务端管理权限。
- pnkx-ui：访客管理顶部“查看页面与功能分析”，包含日期/页面/访客/会话筛选及三种明细视图；保留旧访客列表。
- SQL：001_analytics.sql 建立独立事件表；002_analytics_target.sql 增加视频目标 ID，不改旧访客表。
- 文章正文 25%/50%/75%/100% 位置事件，每次页面访问去重；后台页面排行显示到达底部次数。
- 原生视频 playing/timeupdate/ended/error 事件，支持选择视频、播放位置阈值及目标视频 ID。拖动进度条后的位置不代表完整观看。
- 搜索/评论/AI 按访客、会话、operationId 关联提交和结果，展示成功、失败、停止与成功率。

## 当前边界

内存队列最多100条，浏览器被强制关闭会丢失未发送事件；没有持久离线队列。用户清理存储或跨设备会产生新匿名访客。来源仅采集域名，未提供来源/地域报表。功能结果属于客户端观测，不替代业务审计。页面排行最多100项。注册、多步骤漏斗及历史汇总属于后续阶段，参见开发方案。


## 本轮验证补充

正文几何边界、位置事件去重与页面切换重置、未知视频时长、视频目标归属已加入自动测试。客户端8项、后端校验9项、Mapper绑定2项共19项通过，两个前端生产构建通过。没有连接真实数据库或执行浏览器端视频播放联调。

操作成功率以查询窗口内提交为分母，结果必须同一访客/会话/operationId且发生时间不早于提交。窗口外的结果不回填，因此跨日/跨筛选窗口可能降低成功率；不可直接等同于业务最终成功率。


## 第三批 登录和回复评论

新增 login_submit/login_success/login_fail、reply_submit/reply_success/reply_fail。仅在表单校验通过后记录提交；登录以返回token为成功，回复以接口返回成功数据为准。接口拒绝、网络异常均记录失败。回复请求期间阻止重复提交。回复 targetId 为被回复评论ID，不保存正文或被回复人信息。

pnkx-ui 的功能事件、访问轨迹及操作成功率支持这两类功能。无需新的数据库迁移，仍要求001和002已执行。登录前后保持相同匿名访客和会话；队列发送时服务端认证身份可能已变化，因此身份转换分析以匿名访客和operationId关联，不推断每条事件发生时的登录状态。

本轮客户端9项、后端校验10项和Mapper绑定2项测试通过。真实登录与回复的浏览器端联调、数据库查询仍待完成。

## 第四批 注册激活与内容筛选

- 注册提交/成功/失败与账号激活提交/成功/失败分别记录。注册请求成功不代表账号已激活，注册与激活各自统计操作成功率，不强行跨设备关联。
- 注册表单增加请求中防重复提交；不记录账号、密码和激活令牌。激活请求仅在浏览器挂载后执行，避免SSR执行状态变更请求。
- 首屏业务事件早于app挂载完成时，自动建立页面上下文，后续挂载不重复计PV。
- 后台新增内容ID、目标ID、功能筛选；内容ID需结合页面类型，视频目标ID需结合视频功能，回复目标ID需结合回复功能。功能筛选会过滤所有指标，PV可能为0，页面有口径提示。
- 页面排行查询当前文章/视频标题，不存储历史标题快照；已删除内容保留ID并显示缺失提示。分类等非文章/视频内容暂不解析名称。
- 无新增数据库迁移。真实MySQL标题查询、筛选及浏览器激活链路仍需联调。
